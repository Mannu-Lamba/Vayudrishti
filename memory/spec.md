# VayuDrishti Phase 1 Specification

## Product
Tropical cyclone intelligence mission console for Smart India Hackathon 2026. The operational dashboard remains backed by realistic local mock data. The entire console is now protected by Emergent-managed Google sign-in with secure httpOnly cookie sessions. Claude is an optional analyst layer served through a minimal secure FastAPI proxy; it does not replace the mock dashboard, ML inference, satellite feeds, or MapLibre placeholder.

## Routes and flows
- `/` Dashboard: metrics, operational map placeholder, monitored cyclone, infrared preview, prediction summary, charts, events.
- `/cyclones` Cyclone Monitor: select active mock systems and inspect the selected readout.
- `/satellite` Satellite Intelligence: switch local infrared, water vapor, and visible layer states.
- `/prediction` AI Prediction Center: view mock intensity forecast, confidence, map placeholder, impact window, and charts.
- `/history` Historical Analysis: view seasonal activity chart and mock archive.
- `/about` Methodology & Architecture: inspect the future observation-to-prediction pipeline.
- `/settings` Preferences: change wind units, pressure units, alert threshold, refresh cadence, and scanline display preference; persisted to localStorage.
- Dashboard analyst workspace: Claude modes for concise briefing, methodology explanation, and natural-language Q&A, with loading, retry, error, and local session history states.
- Authentication: unauthenticated visitors see the Google sign-in screen; OAuth callback session fragments are exchanged server-side, `/api/auth/me` verifies the cookie session, and the authenticated header shows profile/sign-out controls.

## Data model
Typed interfaces live under `frontend/src/types/` for cyclones, satellite frames, prediction points, tracks, historical records, user preferences, and analyst messages/requests. Mock records live under `frontend/src/data/mock/`. `frontend/src/services/api.ts` remains the mock boundary; `frontend/src/services/analyst.ts` uses the relative typed stream helper in `frontend/src/lib/api.ts`.

## Claude integration
`POST /api/analyst/stream` streams SSE `delta`, `done`, and `error` events through `emergentintegrations` using the configured Claude model. `GET /api/analyst/history/{session_id}` returns persisted analyst messages from MongoDB. `EMERGENT_LLM_KEY` and `CLAUDE_MODEL` are read from `backend/.env`; the key is never sent to the browser. If the service is unavailable, the existing mock dashboard remains operational.

## Auth
`POST /api/auth/session` exchanges the temporary Emergent `session_id` server-side, stores users and 7-day sessions in MongoDB, and sets the `session_token` cookie with `httpOnly`, `secure`, `samesite="none"`, and `path="/"`. `GET /api/auth/me` is the source of truth (now includes `role`) and `POST /api/auth/logout` clears the current database session and cookie. Analyst messages attach to the authenticated `user_id` while preserving legacy unowned records for the same browser session id.

## Access control (Domain Access, Operator Roles, Session Center, Audit Trail)
- **Domain Access**: `access_policy` collection (single `default` doc) holds `allowed_domains`; seeded once from `ALLOWED_EMAIL_DOMAINS`. Empty list = open access. Enforced at Google exchange (403 with a human message → `AccessDenied` screen via `AuthCallback`) and on every `get_current_user` call (revoking a domain signs out its operators; `/auth/me` 403 renders `AccessDenied`). Denied attempts are audited as `auth.sign_in_denied`.
- **Operator Roles**: `users.role` is `analyst | admin`. Resolution: stored role → `ADMIN_EMAILS` env → first non-test operator bootstraps as admin → analyst. `require_admin` guards `/api/admin/*`. Admin UI: `/admin` Access Control (domain allowlist add/remove, operator role select; cannot change own role or remove own domain when others remain; the first restriction applied to an open allowlist auto-includes the acting admin's own domain so they are never locked out). Frontend hides the ADMINISTRATION nav for analysts and `AdminOnly` redirects `/admin` → `/`.
- **Session Center** (`/sessions`): sessions are per device (`session_id`, `browser`, `os`, `ip`, `created_at`, `last_seen_at`, `expires_at`); sign-in no longer wipes other sessions. `GET /api/sessions`, `DELETE /api/sessions/{session_id}` (current → cookie cleared + client redirect to login), `POST /api/sessions/revoke-others`. `last_seen_at` touched at most once per minute.
- **Audit Trail** (`/audit`): `audit_events` written via `lib/audit.record_audit`. Server-side actions: `auth.sign_in`, `auth.sign_out`, `auth.sign_in_denied`, `session.revoked`, `session.revoked_others`, `analyst.requested`, `admin.domain_added`, `admin.domain_removed`, `admin.role_changed`. Browser-recorded actions (`POST /api/audit/events`, Literal-restricted): `cyclone.selected`, `satellite.layer_changed`, `preferences.saved`, `briefing.exported`. `GET /api/audit/events?scope=mine|all&action=&limit=` — analysts are forced to `mine`; admins can view all operators. "Export handoff log" downloads the filtered events as JSON.
- TS mirrors: `frontend/src/types/auth.ts` (AuthUser, SessionInfo, AccessPolicy, ManagedUser), `frontend/src/types/audit.ts` (AuditEvent, AuditEventCreate, AuditListResponse, action labels). Service boundary: `frontend/src/services/access.ts`.

## Phase 2.1 — Track animation, coastal impact, access-control split (added)
- **Track animation**: `MapTimeline.tsx` adds a play/pause transport button and a stepped speed slider (0.5×/1×/2×/4×, with a live readout) that auto-advances `selectedIndex` on an interval; stops at the last point or when the underlying track changes (switching cyclones). No new types.
- **Coastal impact**: clicking a risk-zone polygon on the map (`RiskLayer.tsx`) opens a MapLibre popup listing coastal districts (from the new mock gazetteer `data/mock/coastalDistricts.ts`, ~24 districts across Odisha/AP/WB/TN/Gujarat/Maharashtra) whose centroid falls inside that zone's radius, nearest first — pure client-side haversine math (`haversineKm`, `districtsInRiskZone` in `lib/geo.ts`). New types `CoastalDistrict`, `CoastalImpact` in `types/track.ts`. Explicitly a Phase-2 mock estimate (centroid distance only, not real polygon intersection) — labelled as such in the popup.
- **Access control split**: `/admin` `AccessControl.tsx` is now a thin composition of three focused components under `components/access/`: `DomainAllowlistPanel.tsx` (domain form + list, owns its own query/mutations), `OperatorRolesPanel.tsx` (operator list + role select), `LockoutGuardPanel.tsx` (read-only explainer of the backend's anti-lockout rules — last domain can't be removed, admins can't demote themselves, own domain auto-joins the first restriction). Shared `errorDetail()` helper moved to `lib/errors.ts`. No backend or behavior changes — same endpoints, same safeguards, reorganised UI only.

## Phase 3 — Multi-region satellite intelligence (added)
- **Two taxonomies, kept separate**: the UI hierarchy (`types/region.ts`, `data/mock/regions.ts`) is `north_indian_ocean` → `arabian_sea` / `bay_of_bengal`, `south_indian_ocean`, `pacific_ocean` → `western_pacific` / `eastern_pacific` / `southern_pacific`. Each region/subregion lists the IBTrACS `basins` it draws from (NI; SI; WP + EP + SP; WP; EP; SP). Region ids are never basin codes. `CycloneData.basin` holds the dataset basin; `lib/regions.ts::resolveCycloneArea` (basin + position) is the only bridge to the UI hierarchy. `HistoricalCyclone` now has `basin: "NI"` + `area: "Bay of Bengal"` (History table shows "Area · basin").
- **Registry**: 9 mock systems — NIO 3 (vd-001..003), SIO 1 (vd-004), WP 3 (vd-005..007), EP 2 (vd-008/009), SP 0 (off-season, exercises the empty state). Non-IMD categories added to `CycloneCategory` (Typhoon, Hurricane, Tropical Storm, …). Tracks for new systems come from `buildMockTrack` in `data/mock/geotracks.ts`.
- **Satellite data** (`data/mock/satellite.ts`): sources INSAT-3D/3DR/3DS, Himawari-9, GOES-18/19, Meteosat-9 (IODC) with per-channel bands; `mockSatelliteAvailability` per region/subregion with coverage tiers (primary/secondary/limb) and a default source (SIO defaults to Meteosat-9, not INSAT); 7 slots 11:30–14:30 UTC on 08 Sep 2026; generated `SatelliteObservation`s with per-source scan offsets (Himawari files 14:20 under 14:30), deterministic gaps (INSAT-3DR 13:00 and GOES-19 12:30 scan gaps, INSAT-3DS 14:30 still processing) and VIS unavailable at local night. Imagery is a procedural, watermarked SVG (`data/mock/satelliteImagery.ts`) — not observed data. `mockSatelliteFrame` remains for the dashboard card.
- **Service boundary** (`services/api.ts`, each function notes its Phase 4 endpoint): `getRegions`, `getRegion`, `getCyclonesByRegion`, `getSatelliteCatalog`, `getSatelliteSource`, `getSatelliteFrame` (320 ms mock latency to surface loading states), `getRegionalCycloneObservation`, `SERVICE_MODE = "mock"`.
- **/satellite**: all state in the URL (`?region, subregion, source, channel, t, cyclone`) via `lib/searchParams.ts::useSearchParamState` (patches a ref so back-to-back updates compose). Components: `components/satellite/` (RegionSelector, SubregionSelector, SatelliteSourceSelector, ChannelSelector, SatelliteControls, SatelliteTimeline, SatelliteViewer [zoom/pan/fullscreen/loading/unavailable states], SatelliteComparison, SatelliteMetadata, RegionalCycloneStatus) and `components/region/` (RegionOverview with subregion indicator tiles — the Pacific overview — and RegionStats). "VIEW ON MAP" → `/cyclones?region=…&subregion=…&cyclone=…&source=…`; `/cyclones` is region-aware and links back. Channel switches still audit `satellite.layer_changed`.
- **Map reuse**: `CycloneMap` gained optional `viewport`, `followCyclone`, `eyebrow/title/tags`, `sectors`, `systems`, `onSystemSelect`, `variant="compact"`, `cyclone: null`; `minZoom` 0 so the Pacific fits a side column. New layers `RegionSectorLayer` (dashed subregion outlines) and `RegionSystemsLayer` (other systems). `MapControls` takes `onReset`. Bounds with `east > 180` express antimeridian-crossing sectors.
- **Local verification** (no MongoDB here): Vite dev server + Playwright with `/api/*` stubbed (auth/me, audit, sessions, analyst history).

## Phase 4 + 5 — AI prediction workspace + API integration architecture (added)
- **Two data modes**: `VITE_USE_MOCK_DATA=true` (default, DEMO MODE) or `false` (LIVE API). `src/config/environment.ts` reads `VITE_API_BASE_URL` (default `/api`), `VITE_USE_MOCK_DATA`, `VITE_API_TIMEOUT_MS`, `VITE_PREDICTION_STRATEGY` (`resource` = GET /api/cyclones/{id}/prediction, `inference` = POST /api/ml/predict). `frontend/.env.example` + `frontend/API_INTEGRATION.md` document them and every endpoint contract. Runtime "Use demo data" fallback lives in `services/dataMode.ts` (sessionStorage).
- **Service layer** (`src/services/`): `apiClient.ts` (base URL, JSON, timeout, typed `ApiError` with `kind`/`status`, `describeApiError`, `orNullOn404`, `checkApiHealth`) replaced `lib/api.ts`; `regionApi`, `cycloneApi`, `satelliteApi`, `predictionApi` replaced the old `services/api.ts`. Every function is `serve({ demo, live })` and returns `{ data, source }`. Only services import `src/data/mock/*`.
- **Hooks** (`src/hooks/`): `useServiceQuery` (React Query; keys `["vd-data", mode, …]`; retries transient errors in live mode only), `useDataMode`, `useApiStatus`, `useRegions`/`useCoastalDistricts`, `useCyclones`/`useRegionalObservation`/`useCycloneArchive`/`useArchiveSummary`/`useRecentEvents`, `useCyclone`/`useCycloneTrack`/`useCycloneHistory`, `usePrediction`/`useMlAssessment`/`useModelRegistry`, `useSatelliteCatalog`/`useSatelliteObservation(s)`/`useLatestSatelliteFrame`.
- **Types**: `types/api.ts` (DataSource, ServiceResult, Paginated, ApiConnectionStatus), `types/model.ts` (ModelStatus ready|processing|unavailable|not_connected|error, ModelInfo, ModelRegistry, MlDetect/Classify/Predict contracts, PredictionResourceResponse), `types/prediction.ts` (CyclonePrediction, ForecastPoint with 0–1 confidence + uncertaintyRadiusKm, PredictionAnchor, PredictionUncertainty), `types/track.ts` (`CycloneMapScene`, `GeoTrackPoint.uncertaintyRadiusKm`), `types/cyclone.ts` (CycloneArchiveQuery, ArchiveSummary, OperationalEvent).
- **Mock data**: `data/mock/predictions.ts` now holds demo predictions shaped exactly like the API payload (VD-009 intentionally has none → "No prediction available"); `models.ts` (model status/info), `events.ts`, `mockArchiveSummary`. VD-001 forecast pressures aligned to 973/969/965/960 hPa.
- **/prediction** (`?region&subregion&cyclone=<id|code>&h=<hours>`): selector, current status, summary cards at the selected horizon, horizon timeline (CURRENT, T+6…T+24; any horizons), prediction map (reused CycloneMap with a scene built by `lib/mapScene.ts::sceneFromPrediction`; forecast points clickable and highlighted; per-point uncertainty circles + corridor), forecast detail, confidence (track/intensity from prediction, classification/detection from /ml/classify + /ml/detect), uncertainty panel, intensity + pressure charts with selected-horizon marker, model status, model info. Components in `components/prediction/`.
- **Map**: `CycloneMap` renders a supplied `scene` or loads the track via `useCycloneTrack`; no mock imports. `PredictionLayer` takes `selectedId`/`onSelect`, draws uncertainty circles and uses per-point radii or a backend polygon. `RiskLayer` gets coastal districts as a prop.
- **Common UI**: `DataSourceBadge`, `ApiErrorState` (Retry + Use demo data), `LoadingBlock`, header `ApiStatusIndicator`. Dashboard now data-driven (metrics, regional status panel to pick a cyclone, compact model status, events via service); History pages through the archive service.

## Phase 6 — Map ↔ API integration (added)
- **Data flow**: page → hook → `cycloneApi` → `apiClient` → FastAPI → hook state → `CycloneMap`. `CycloneMap` is presentational: props `cyclones` (`MapCycloneMarker[]`), `selectedCycloneId`, `onCycloneSelect`, `scene`, `districts`, `status` (loading/error overlay), `viewport`; it never fetches. `hooks/useCycloneMap.ts::useCycloneMapData(id)` = track + prediction + districts → scene.
- **Service**: `getCyclones(CycloneQuery)` — region, subregion, basin, startDate, endDate, active. `getCycloneTrack` returns `CycloneTrackResponse` (wire `TrackPoint[]`: ISO timestamp, lat/lon, windKmh, pressureHpa, optional category/forecast/confidence) normalised by `normalizeTrack` (lead times + labels computed in the frontend). Demo tracks (`mockTrackResponses`) go through the same adapter and carry observed fixes only; forecasts come only from the prediction service (VD-009 shows none).
- **Markers**: every system drawn (`CycloneMarkersLayer`, hover details, click selects); selected system uses the DOM `CycloneMarker`; colour = API category via `config/cycloneCategories.ts` (design-guideline IMD palette, other RSMC labels by equivalent wind band, unknown → neutral; never inferred from wind).
- **Viewports**: `config/mapViewports.ts` (`MAP_VIEWPORTS` per UI region/subregion id; `describeSelection().viewport`).
- **/cyclones**: `?region&subregion&cyclone=<id|code>`; cyclone-only URLs resolve their region; unknown/out-of-view cyclone params are cleared; region/subregion switches keep the selection only if it is inside the new view. `CycloneDetailPanel` (ID, name, category, status, wind, pressure, coordinates, timestamp, region, subregion, basin, track/forecast state, View satellite, View classification — enabled only when /ml/classify returned a result). Dashboard "View on map" → `/cyclones?…&cyclone=…`.
- **Status labels**: Demo mode / Live API / API offline. Cyclone data errors read "CYCLONE DATA UNAVAILABLE — Unable to retrieve cyclone information." with Retry + Use demo data.

## ML stage 1 — Cyclone identification model (added)
- **Where**: `identification_model/` (own venv, config, README). Binary CYCLONE / NO_CYCLONE image classification; the datasets carry no bounding boxes, so no object detection.
- **Data**: Dataset A = PS-70 finalized IBTrACS metadata + positive candidate workbook; Dataset B = PS-70 GridSat-B1 non-cyclone pool (North Indian Ocean only). Originals stay outside the repo (paths in `configs/config.yaml`), snapshotted with SHA-256 into `data/raw/` and verified unchanged. Both classes are re-imaged from NOAA GridSat-B1 IR (18°×18° OPeNDAP crops) so the model cannot learn the HURSAT-vs-GridSat difference; the original PS-70 PNGs are stored south-up.
- **Dataset v1.0**: 2,000 positives (IBTrACS nature TS only, 1,118 storms, 6 UI subregions × weak/medium/strong) + 2,000 NIO negatives (easy/moderate/hard by a cold-cloud rule; 452 hard). Storm/event-grouped 70/15/15 split (seed 42); leakage check PASS.
- **Model**: EfficientNet-B0 (ImageNet) → 2 classes, best epoch by validation F1. Held-out test (601 images, 169 unseen storms): accuracy 0.962, precision 0.964, recall 0.961, F1 0.962, ROC-AUC 0.992, PR-AUC 0.991; NIO-only F1 0.906; hard-negative FPR 13.4 %. Other basins: recall only (no negatives). Full report `identification_model/reports/model_report.md`.
- **Backend hook**: `from src.inference import predict_image` → `{success, prediction{class, confidence}, probabilities, model{name, version}}`; not wired into `backend/` yet.
