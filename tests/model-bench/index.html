Trained models on held-out data

Each card below is a real request to the FastAPI backend, which runs the model that is loaded in memory. The images and storms come from the test splits, so none of the models saw them in training. They are a random draw (seed —), and wrong answers are kept. The full-test-set numbers are read from each model's evaluation report.

Your own images · POST /api/ml/analyze

Upload any cyclone image

Any satellite, channel or source, including images saved from the web. Each file runs through identification, then intensity classification, then a track forecast if you give the storm ID. Nothing is stored.

The models were trained only on GridSat-B1 infrared (~11 µm) scenes: single channel, cold cloud tops bright, about 18°×18° centred on the system. Every result shows how your image differs from that. Colour-enhanced, visible or water-vapour images still get an answer, but it is less reliable. The middle picture is exactly what the networks see: grey and stretched to 224×224.

The four IMD groups are D/DD, CS/SCS, VSCS and ESCS/SuCS. Labels come from the IBTrACS 1-minute wind (USA_WIND). ✓ marks the true class, the blue bar is the model's pick, and "One class off" means it chose the neighbouring intensity group.

Observed track Forecast time T0 Model forecast Where the storm actually was Empirical uncertainty radius

For each held-out test storm the model sees only the 24 h of observations before T0. The storm's later fixes are used only to check the forecast. Confidence is not produced by the model; the radius is the distance that held 67 % of validation track errors. AI decision support, not an official IMD/RSMC forecast.

Everything runs on this machine: the page is at localhost:3001, and the models are in the FastAPI process on 127.0.0.1:8001. The page never loads a model file.
